# Purpose

Owns the frontend application source: React routes, UI, domain rules, data loading, persistence, workers, and shared libraries.

## Ownership

- `App.tsx` owns live route composition and much of the mobile UI shell.
- `domain/` owns feed/filter/share/recommendation types and pure business rules.
- `services/` owns catalog loading, detail loading, and external data-source integration.
- `store/` owns local persistence and migrations.
- `workers/` owns background computation paths.
- `assets/`, `lib/`, and `db/` support source-level UI/data helpers.

## Local Contracts

- Read the root AGENTS.md first.
- Keep frontend data consumption compatible with `manhwa_db/db/exports/frontend`.
- Prefer the optional chunked `weeklyHistory` dataset for runtime growth and fall back to full `history` for older manifests. Recommendation descriptors are optional; recommendations remain suspended and must not be downloaded during normal sync.
- Do not make the frontend read backend raw, processed, enrichment, cache, or state files.
- Release-date sorting and date-window filters use only `published.start_date`. Estimated start dates remain in their estimated chronological position; titles without a start date are excluded, and discovery/update timestamps are never substituted. A catalogue-normalization version may trigger one deliberate cache repair when a shipped rule previously stored incorrect date values; it must not become a general app-version sync trigger.
- Do not add a blanket no-recognized-tag exclusion unless the user explicitly asks; backend/API tag coverage can differ from the MangaBaka site.
- Installed PWA users may already have IndexedDB state; migrations must be backward-compatible and recoverable.
- The default PWA identity is `Aeon`; preserve an intentionally customized app name in saved user settings.
- Home pager behavior is protected and user-visible: mobile horizontal feed swipe, per-feed vertical scroll, detail back, and route/session restore must keep the stable `9f16d14` behavior baseline. Desktop changes feeds through its paired header arrows and keeps trackpad input on the active feed's vertical axis.
- Do not reintroduce commit `6b05599` behavior, `HOME_FEED_PREVIEW_TITLES = 18`, delayed route wrappers, hidden-pane vertical restoration, or delayed post-swipe scroll corrections.

## Work Guidance

- Use existing domain helpers and types before adding new state shapes.
- Keep rendering cheap on mobile; avoid expensive blur, image extraction, or large list updates in scroll handlers.
- Keep custom-feed Add search work out of normal Home rendering. Catalogue filtering and Fuse indexing for Add mode must be created only after Add mode opens, and deferred so the mode can paint before that work starts.
- Reuse pure Home feed-query results across Home unmount/remount only while every query input keeps the same reference or value. Catalogue, history, tags, labels, settings, feed, or metadata changes must invalidate the result immediately; do not add timers or background refresh work for this cache.
- On a Home mount, render the active feed before preparing adjacent feeds. Warm adjacent feeds in bounded nearest-first steps after the first frame; do not mount the full nearby radius before Home can acknowledge navigation.
- Initial Home pager alignment may set the pager's horizontal position before pager ownership is enabled. It must not use a whole-element scroll that can force vertical layout, and it must never become a delayed correction after user movement.
- Route/detail navigation should respond immediately, even if details or recommendations are still loading. A title route may retain only the page that opened it: Home behind details opened from Home, and Updates behind details opened from Updates. Opening from one route must never mount another heavy route in the same response frame.
- Home stays mounted behind a title overlay so detail Back reveals the same feed tree. Feeds, Search, and Settings own separate routes and must not keep a hidden Home pager alive behind them. Returning through Home rebuilds from the saved active feed and per-feed scroll state.
- Home owns its pager and per-feed scroll restoration. The global session restorer exclusively owns the last route and must not read or write Home pane positions; Home scroll events must never mutate route state. Initial route restoration completes before normal route persistence starts, so opening at `/` cannot erase a saved non-Home route. During cold startup, the library loader overlays the mounted pager instead of replacing it, and automatic pager/pane scroll events remain non-persistent until initial alignment has completed. A missing or unmounted Home scroller must never be treated as `scrollTop: 0`; only a measured mounted pane may overwrite its saved position. The feed's expanded result count must persist with its layout key, so a cold resume renders enough rows before restoring a deep saved scroll position. Do not clamp or rewrite that count while the catalogue is unavailable, because a transient empty query would destroy the deep resume state.
- During a required cold-start catalogue update, the app-level library loader must remain opaque and above navigation on normal app routes until the verified catalogue is saved and committed to React state. Render that blocker at the document root, lock page overscroll, and make the underlying app inert so mobile pull/overscroll cannot expose or activate navigation. The mounted Home pager may prepare underneath it, but empty feeds, zero title counts, and navigation must never become visible or interactive. Shared-feed links use the same root blocker with shared-feed wording; shared-title and non-feed import routes retain their dedicated loading surfaces. A failed update may fall back to a previously validated IndexedDB catalogue; a first install with no valid cache remains on the loader and offers Retry instead of opening an empty app.
- Entering or leaving a temporary Home segment preview changes the pager's feed array. Reset pager ownership before that realignment and re-enable scroll-driven warming afterward; otherwise feeds outside the initial render radius can remain permanent skeletons.
- Feeds-page mosaic preparation processes only the selected library's visible feeds and yields between feed queries. It must be cancellable on unmount so background mosaic work can never block bottom-nav input or delay Home paint.
- Catalogue cover cards use native same-document hash anchors for detail routes so hundreds of mounted cards do not subscribe to every bottom-nav route change. Preserve the existing title URL, Back behavior, selection interception, and pre-navigation preparation.
- Opening a shared feed link has no Add preview. While its required library data initializes, show the same app-owned database spinner and progress treatment as normal library preparation instead of a plain text waiting state. Clone the feed to a new local ID, place logic feeds in LIST/UNSEGMENTED or custom feeds in MY LIST/UNSEGMENTED, open it directly on Home, and replace the import history entry. Broader settings/full imports retain confirmation.
- Shared title links use the direct `/title/:id?shared=1` hash route, never a compressed catalogue payload. The title detail request may render independently while first-run catalogue sync continues. Shared-launch Back returns to Home, where unfinished catalogue work uses the normal library loader; internal title Back behavior remains unchanged.
- Feed sharing always offers both the compressed link and a single-feed JSON download. Importing JSON without segment metadata merges regenerated feed copies into LIST/UNSEGMENTED or MY LIST/UNSEGMENTED by feed kind; segment JSON preserves and imports its segment.
- A successful Copy action closes the share drawer and its underlying feed menu, then shows a short app-styled `Link copied` toast. Support LAN-phone previews with a user-gesture `execCommand` fallback when the secure Clipboard API is unavailable; do not use browser alerts.
- LIST owns logic feeds and MY LIST owns fixed-membership custom feeds. Each library has independent segments and UNSEGMENTED placement, while the saved root library order controls their Home sequence. Existing state without library fields migrates to LIST without changing feed IDs or behavior.
- The Feeds page remembers its last selected LIST/MY LIST tab for the browser session. Opening a feed and returning with Back must restore that tab; this page-tab memory must not alter Home library order, the active Home feed, or persistent library contents.
- Custom feeds store at most 500 unique catalogue IDs. Membership is never changed by filters; manual order is fixed, automatic order uses the saved sort rules, and unavailable catalogue IDs remain stored for future recovery/import compatibility.
- `CREATOR FAVOURITES` is a built-in MY LIST segment containing the fixed `MY FAVOURITES` custom feed. It installs additively for fresh and existing libraries, starts visible on Home, and must not replace or duplicate an existing copy with the same stable IDs. The old supplied description `Sorted by Personal Ratings` migrates to `Sorted by the Creator's Ratings` without replacing membership or settings.
- Custom compact settings include title, a conditional description field, mobile/desktop grid, rank and cover-stat visibility, insertion placement, non-AniList placement, and the shared popularity, Fan Rank, chapter, status, sort, and rolling-period presets. New custom feeds start in Automatic mode sorted by Fan Rank; existing saved order modes remain unchanged. Advanced settings keep exact min/max parameters behind a visible named Add chooser alongside manual rolling date/window controls, Manual/Automatic mode, cover-stat choices, and existing multi-sort rules. Logic tag/source and content-rule controls are not supported there and must not remain active as hidden filters after save.
- Preset sorting exposes `High first` and `Low first` directly below Sort by. Changing the sort metric preserves that direction. Advanced custom multi-sort continues to own each rule's separate direction.
- Logic and custom feed settings expose multi-select exact Release year presets from the current year back to 2014 in a collapsed row within the main Presets panel. Enter it from the custom title-selection dock and keep its Done confirmation as a small centered bottom pill above main navigation, not a full-width surface or header overlay. Use explicit app-style glass drag handles and a readable cover-only drag ghost with no title label. Position the ghost at the pointer immediately on pickup so it never flashes at the viewport origin. The window owns the active pointer stream so moving/re-rendering a card cannot strand the drag. After a deliberate stable hover, move an empty source-sized placeholder to the prospective drop slot; while the pointer is outside the title grid, auto-scroll may continue but the placeholder must not chase passing cards. Do not rerender order continuously for every pointer movement. Keep hidden filtered IDs in place and restore swipe immediately when the mode closes; do not rewrite pager ownership.
- If changing feed settings, custom feeds, folders, or profiles, update migration and serialization paths together.
- Built-in default feeds use the compact settings drawer: grid columns, rank visibility, cover-stat visibility, optional Completed/Hiatus status filtering, and the Official English link filter only. Released and Completed period purposes retain their independent 1 Week, 1 Month, 3 Months, 1 Year, and advanced fixed-date controls. Manual min/max parameters, manual rolling dates, multi-sort, sources, multi-status, content ratings, and cover-stat details belong under Advanced as applicable. - Keep the detail loading placeholder lightweight: preserve only the above-the-fold identity, stats, and description shapes, animate them as one group, and honor reduced-motion preferences. Do not create one independent shimmer animation per placeholder.
